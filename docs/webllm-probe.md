# Separate model failures from migration failures

Open the isolated probe at **http://127.0.0.1:8001/**. Its historical default is WebLLM 0.2.86; select 0.2.87 to match the current main migration interface. It supports exact Qwen and Llama model IDs, but imports no project migration code and exposes no database API. It is adapted from the official example, not an unchanged upstream reproduction.

## Quick path

1. Close other model tabs to release GPU memory. This port is a separate origin: cached assets may need to download again after explicit loading.
2. Choose runtime **0.2.87** and **Llama-3.2-3B-Instruct-q4f32_1-MLC**, then **Load selected model**. Use Qwen options only for reproducing earlier comparisons.
3. Keep **Plain** output mode. Run **1. Minimal plain completion**, then **2. Exact source-value copy**. Inspect each raw result.
4. Run **3. Single relational record** and **4. Single MongoDB document** once each.
5. Download **webllm-isolated-probe.json** before closing the tab. It contains exact prompts, raw responses/errors, model-library URLs, usage, and timings. Review before sharing.
6. Compare cases 2–4 in **JSON object + explicit schema** mode. A grammar exception is evidence, not a reason to silently fall back. Then unload and repeat with 0.5B if useful.

### Explicit-schema compatibility correction

The original report reproduced `Cannot pass non-string to std::string` with `response_format: {type: "json_object"}` and no schema. [WebLLM v0.2.86](https://github.com/mlc-ai/web-llm/blob/v0.2.86/src/llm_chat.ts#L1040-L1065) routes that explicit type to `compileJSONSchema(responseFormat.schema!)`; the TypeScript assertion does not supply a default string. Supplying a JSON-stringified schema resolved that initialization error in the subsequent real browser case. It did not fix Qwen's altered source values.

Schemas constrain types, fields and nesting only. They do not contain `const`, enums, or expected source values such as `caterpie`; a correct name must still be generated by the model and checked independently. Plain mode remains unchanged. The report preserves the actual schema string sent, allowing comparisons with earlier reports.

Published 0.2.87 retains the explicit-schema branch. The actual Qwen3B copy result was unchanged across 0.2.86 and 0.2.87 (`caterpie` became `cassiepie`); q4f32 also altered the value. The later Llama comparison passed copy, relational and MongoDB single-record cases. The main application now uses 0.2.87 with Llama recommended. These observations do not establish a universal model or GPU root cause.

## Compare 0.2.86 and 0.2.87

1. Run case **2. Exact source-value copy**, mode **JSON object + explicit schema**, model **3B**, runtime **0.2.86** once.
2. Select runtime **0.2.87**. Running is blocked until **Load selected model** succeeds; the old engine is unloaded before the new package initializes.
3. Run the identical case once and download one report containing both versions. Do not reload the page between runs.

Only those two hard-coded package URLs are selectable. Each package supplies its own official `prebuiltAppConfig`; model-library URLs may change with the release. Therefore this compares official release configurations (JavaScript plus its paired WASM), not a controlled isolation of JavaScript alone. No custom cross-version WASM mixing is performed. Public model-asset branches remain mutable and model weights are not hashed by this harness.

Report format version 2 records `runtime_version` and `runtime_url` on each load and case, alongside that load's model record. Older reports used top-level `version`; do not treat a mixed-version report as a single runtime. Changing the dropdown never relabels a previously loaded engine or earlier results. Imports/downloads occur only on explicit load; changing selection alone makes no network request. A failed new-version load is reported without silently reverting to the old runtime.

## Compare the 3B q4f16 and q4f32 variants

Keep runtime **0.2.87**, case **2. Exact source-value copy**, and **JSON object + explicit schema**. Run once with `Qwen2.5-3B-Instruct-q4f16_1-MLC`, select `Qwen2.5-3B-Instruct-q4f32_1-MLC`, load it explicitly, and run once more. Download the combined report without reloading the page. The old engine is unloaded before the new one loads; cached files are not deleted.

The q4f32 ID and its paired WASM exist in the [official 0.2.87 registry](https://github.com/mlc-ai/web-llm/blob/v0.2.87/src/config.ts). Its registry memory estimate is about 2,894 MB, versus about 2,505 MB for q4f16; actual browser memory can differ and a separate asset download may be needed. Both variants remain four-bit quantized models; this is not an unquantized full-precision model comparison. Their configured arithmetic/library paths and model artifacts differ, so a difference would justify further investigation, not prove a specific GPU fault. This optional comparison does not change the main interface selection.

Start manually from the project directory: `.venv/bin/python webllm_probe.py --port 8001`.

## What the result establishes

### Compare another model family

The [official WebLLM 0.2.87 registry](https://github.com/mlc-ai/web-llm/blob/v0.2.87/src/config.ts) includes `Llama-3.2-3B-Instruct-q4f32_1-MLC` with its own paired WASM and an estimated 2,951.51 MB VRAM requirement. It is available in the probe and recommended in the main interface after successful real single-record tests. Review the [upstream model card and license terms](https://huggingface.co/meta-llama/Llama-3.2-3B-Instruct) before loading. The [MLC model card](https://huggingface.co/mlc-ai/Llama-3.2-3B-Instruct-q4f32_1-MLC) identifies the underlying Llama model.

Keep runtime **0.2.87**, case **2. Exact source-value copy**, and **JSON object + explicit schema**. Select Llama, explicitly load it, run the case twice, and download the report without reloading the page. Selection alone neither downloads weights nor runs inference; loading unloads the previous engine. Copy prompts, schema and settings stay identical. This changes model family, weights, tokenizer and paired model library together: it can distinguish observed behavior but cannot identify one internal cause on its own. Expected values are not forced into the schema. A successful two-field copy is not proof of full database migration.

| Observation | Meaning |
|---|---|
| Minimal plain completion fails | Failure is reproducible outside database/migration logic; retain exact model/runtime evidence. |
| Plain exact copy changes Caterpie | Source-fidelity failure occurs even without batching or migration prompts. |
| Plain works but JSON mode throws | Investigate the pinned runtime's grammar/model-library path separately. |
| All isolated cases pass | Migration-specific state/prompt differences remain a hypothesis; full migration is not proven. |
| Isolated output contains corrupt characters | Corruption is reproducible outside migration code; its cause still needs investigation. |

Each case awaits `resetChat()`, then executes one nonstream completion without retries. Expected values are used only for a local diagnostic comparison, never supplied as a replacement response or written to a destination. JSON is parsed strictly: Markdown fences are not removed. A false exact match can mean JSON syntax, extra/missing fields, or changed values; inspect raw evidence. Key order is ignored; array order and exact values are retained.

Reports retain the latest 20 cases and 20 load events in memory. Response JSON is capped at 64,000 characters; raw content and retained load, completion, reset, or parsing error strings are capped at 32,000. Error prefixes are preserved with `error_clipped` and `error_original_characters` (or corresponding `parse_error_*` fields). Reloading loses the report. This caps retained output, not runtime internal allocation. No telemetry, database credentials, or source database file is collected. Model files still download from public upstream URLs; URLs/configuration may change even with a pinned JavaScript version. GPU backend, driver and device faults are not automatically distinguished by this harness.
